## C · 技术债（现存，登记偿还条件）

### C4 · 网关/BFF 免认证清单靠人工维护

- **现状**：登录/回调等公开路径靠白名单登记。
- **风险**：忘登记 → 上线 401；登记过宽 → 裸奔。
- **偿还**：openapi 工具加"公开路径与免认证清单 diff 校验"（工具演进，约 2 天）；短期靠 review checklist。

### C5 · 大数据量列表未做虚拟滚动/游标分页

- **现状**：常规分页（page_size ≤ 100）。
- **偿还条件**：出现单页 >1000 行运营场景 → 上虚拟滚动或游标分页（架构已约定 P4 起大数据量改游标）。

### C9 · Gotenberg 无队列/限流（v2 新增）

- **现状**：合同打印稿渲染直接 HTTP 调用，并发大时 Chromium 吃内存。
- **偿还条件**：渲染并发 >10/s 时前面加队列（复用 RocketMQ 异步导出管道模式）+ 容器资源 limit。

### C10 · 轮询接口的连接开销监控（v2 新增）

- **现状**：500 并发用户 × 10s = 50 QPS 轻量查询，无压力。
- **偿还条件**：管理后台并发 >500 或轮询间隔需要缩到 5s 以下时——优先考虑升级 WebSocket（见 D5），而不是继续缩短轮询。

## D · 替代方案与架构演进建议

> 每条：当前 → 备选 → 推荐与理由 → 触发条件。**没有一条是"现在必须改"**；价值在于情况变化时决策依据已写好。

### D1 · 仓库策略：5 仓（含 micro-frontend 前端合仓）✅ 已定稿

- 维持 5 仓：common / server / **frontend** / desktop / deploy。
- **重评条件**：前端 ≥4 人或小程序团队独立 → 按 apps 目录 `git filter-repo` 抽仓（目录边界即拆分边界）；团队 ≤4 人也可整体合回单仓，成本很低。

### D2 · Saga 编排器：自研 → Temporal ✅ 已定稿（维持自研）

- 触发重评：编排流 ≥3 条或多天级人工节点 → 届时迁 Temporal，不提前迁（单流场景负收益）。

### D3 · 检索：MySQL → Elasticsearch

- 维持 MySQL。升级路径：①MySQL 全文索引（ngram）→ ②仍不足再 ES/OpenSearch（只加检索代理查询路径，写路径经事件同步）。触发：核心列表 P95>1s 或真全文检索需求。

### D4 · 时序层：TDengine 与监控指标分工

- 3 年目标（1.7 亿条/日）时 TDengine 扩 3 副本；Prometheus 指标保留 >90 天时加 VictoriaMetrics **只做监控长期存储**；两者不合并（查询模式不同）。

### D5 · 实时性：轮询 ✅ 已定稿，WebSocket 为升级项

- 当前：10s 轮询增量 + 微信订阅消息异步触达（无推送组件）。
- **升级条件**（满足其一再评估引入 WebSocket 组件或自研网关）：①告警时效要求进到秒级；②"派单即时弹窗"成为硬需求；③轮询接口压力逼近 C10 阈值。接口层只需把 usePolling hook 换成订阅实现，业务代码不动。

### D6 · 认证：自研会话中心 ✅ 已定稿（维持自研）

- 互斥/踢人/封禁即时生效是有状态会话语义，标准 IdP（Keycloak/Ory/Zitadel）面向无状态 OIDC，即时作废是弱项；自研收敛在 sessionx+authz 两包。
- **重评条件**：对外开放平台（对外发 OIDC token）或 3+ 外部 IdP 联邦 → 首选 **Zitadel**（Go 原生，优于 JVM 系 Keycloak）。

### D7 · 任务调度：RocketMQ 延迟消息 ✅ 已定稿（维持）

- 新增约定：所有内嵌 cron 扫描任务（SLA/巡检生成等）在**注册表登记 + 暴露 last_run 指标**（避免黑盒）；服务数翻倍再评估收敛独立 scheduler。

### D8 · 协议适配层独立

- OCPP 当前是 iotingest 内置模块。接入协议 ≥3 种（MQTT/OCPP/Modbus/厂商私有）时拆 `protocol-gateway` 独立部署（每协议一部署单元，共享"五指标→MQ"契约）。

### D9 · 前端微前端化（不建议）

- 明确不做 qiankun/module federation。唯一例外：未来"客户系统内嵌我们的设备监控组件"需求 → 做独立 iframe 微应用，不做全站微前端。

### D10 · 配置中心：Nacos ✅ 已定稿

- Nacos 只做配置（多语言 SDK/管理台/回滚/秒级推送）；服务发现仍 etcd（go-zero 原生）。自研 config 服务已删除。
- **重评条件**：多集群服务发现需求 → 评估 Nacos 发现（需社区 go-zero resolver 插件转正）。

### D11 · 灰度发布能力

- APISIX 具备 traffic-split（按 header/权重）但未启用业务灰度。建议多端上线后第一个迭代启用：新功能先放 5% 内部账号；配合 Nacos 灰度开关（配置秒级生效）双通道。

### D12 · ER 文档自动化（ercheck）

- 建议新增 `ercheck` 工具：解析 migrations 的 CREATE TABLE 自动生成实体清单 + 与 ER 文档 diff（对齐 openapi 漂移检查思路），成本 2~3 天，防文档腐烂。
