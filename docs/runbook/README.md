# runbook · 运行手册规范（S0-06）

**每服务上线前，在本目录补同名 runbook（`<服务名>.md`）**，五节固定结构；`tools/dodcheck` 校验五节齐全（0 FAIL 才可合并，02 §11 上线 DoD）。首个 runbook 随 S3-05 identity 落地。

## 五节结构

1. **职责与依赖**：一句话职责；上下游依赖清单（出站依赖登记《02-技术文档》§10 韧性策略表的一行：超时预算/重试/熔断/降级行为）
2. **健康指标**：RED 指标（QPS/错误率/P99）、关键业务指标（`micro_*` 命名空间）、健康检查端点与 Grafana 看板链接
3. **常见故障**：症状 → 定位（Jaeger trace_id :36686 / Loki 按 trace_id/服务检索）/ 处置步骤
4. **发布与回滚**：发布步骤、迁移注意事项（只前向兼容、两阶段发布）、回滚口径
5. **紧急操作**：降级开关（configcenter 正本路径）、kill 开关、人工介入队列入口

## 约定

- 与服务同名、同生命周期：服务创建（tools/newsvc）即建 runbook 骨架，上线前填全
- 出站依赖变更（§10 韧性策略表）与告警规则变更须同步回写 runbook
- 排障入口总则见《02-技术文档》§11（可观测性）与附录 C（E1~E18 坑速查）
