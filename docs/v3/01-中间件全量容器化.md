# v3-01 · 中间件全量容器化（独立 compose，不占旧环境）

**版本**：v3.0 ｜ **日期**：2026-10-06
**性质**：所有者新增需求项，**方向已定稿**；文中端口号为建议稿（落地前按 §4 冲突核对规则执行后回写）
**需求编号**：NFR-ENV-001（v3 新增，平台能力/环境类）

---

## 1. 需求描述与口径

宿主机上已存在一套 Docker 环境，且本项目所需的全部中间件/服务已有旧的一套在运行（旧 micro 项目遗留：MySQL、Redis、TDengine、RocketMQ、EMQX 等）。所有者要求：

1. 本项目**全部中间件重新起一套**：不复用、不占用宿主机已有的服务和端口；
2. 例如 MySQL 需要 8.x → 自行拉取新版镜像、自配密码、把 compose 写到对应文件夹下；
3. 允许按服务分文件写，**或写一个全量的**（本方案选全量单文件，理由见 §3）；
4. 数据**挂载卷该挂的挂**——有状态数据全部持久化，容器删了数据不丢；
5. **新起的服务和端口号必须在文件中备注**，并同步登记表（双登记，见 §4）；
6. **前后端启动的应用服务不用管**（不在容器化范围）：18 个 Go 服务仍按 v2/03 清单本机 `go run` 启动，端口沿用 v2/02 §4.3；各前端 dev server 同理。

### NFR-ENV-001 验收要点

| # | 要点 |
|---|---|
| 1 | `docker compose up -d` 一条命令拉起全部中间件（按 profile 分组可选起） |
| 2 | 宿主机端口与宿主机已有服务零冲突（官方默认端口一律不用） |
| 3 | 数据落卷：`compose down && up` 后数据不丢 |
| 4 | 端口/账号在 **compose 注释 + env.md 登记表**两处一致 |
| 5 | 真实密码不入库（`.env` 进 .gitignore，`.env.example` 占位入库） |

## 2. 目录与文件（micro-deploy 仓）

```
micro-deploy/compose/dev/
├── docker-compose.dev.yml      # 全量单文件（顶层 name: micro-dev）
├── .env.example                # 端口/密码占位 + 注释（入库）
├── .env                        # 真实值（gitignore）
├── mysql/init/01-app-user.sql  # 建应用账号并授权 micro_% 库（业务库由 tools/migrate 自动建）
├── rocketmq/broker.conf        # listenPort/brokerIP1 与端口映射自洽（§7）
├── emqx/bootstrap.sh           # 幂等建认证器/ACL/平台账号（v2 E6）
├── apisix/config.yaml          # 配置存 etcd prefix=/apisix
├── prometheus/prometheus.yml   # 抓取 host.docker.internal:91xx（§7）
├── prometheus/rules/*.yml      # 三级告警规则
├── grafana/provisioning/       # 数据源 + 看板自动装配
├── loki/loki-config.yml
└── promtail/promtail-config.yml
```

- compose 顶层 `name: micro-dev`，容器名统一 `micro-dev-<服务>` 前缀，与宿主机旧环境的容器一眼区分；
- 独立网络（如 `micro-dev-net`）+ 独立 named volume（`micro-dev_` 前缀），与旧环境零共享；
- 全部服务 `restart: unless-stopped`——v2 附录 D"独立容器不自启"的坑随全量 compose 化自然消除。

## 3. 形态：全量单文件 + profiles 分组

为什么选**全量单文件**（而不是每服务一份 compose）：

- 一条命令起/停/重建全部；环境重建（v2 §11.4 灾后恢复三件套）从"多文件逐个 up + 手动 start 独立容器"简化为 `compose up -d` 一条；
- 端口、卷、密码集中在一份文件 + 一份 `.env`，登记表不会散落；
- "只想起一部分"的诉求由 **profiles** 满足，不需要拆文件。

| profile | 内容 | 何时起 |
|---|---|---|
| **core** | mysql / redis / etcd / tdengine / rocketmq-namesrv / rocketmq-broker | 日常开发必起（五件套，envcheck 对象） |
| **edge** | emqx / apisix / nacos / minio(+init) / gotenberg | 联调 IoT、网关、文件、合同 PDF 时起 |
| **obs** | prometheus / grafana / loki / promtail / jaeger / alertmanager | 排障、阶段验收、演示时起（**D4 方案 A 的"可选启动"落点，见 v3-03**） |

```bash
# 在 .env 里一处控制（免敲 --profile 参数）
COMPOSE_PROFILES=core,edge,obs    # 日常全量；想省内存可只留 core

# 或命令行显式指定
docker compose --profile core up -d
```

**明确不引入的容器：RocketMQ Proxy**（v3 README 总表 #4 定稿）。本项目 Go 侧用 rocketmq-client-go/v2（remoting 协议，直连 NameServer 是它的原生路径），gRPC 版 v5 客户端才是 proxy 的目标用户；"多语言"需求当前落在配置中心（Nacos），MQ 事件总线是纯 Go 内部链路。触发升级时（评估 v5 gRPC 客户端/跨语言生产消费、K3s 计算存储分离）成本极低：broker Local 模式开 `--enable-proxy`，或 Remote 模式加一个容器——端口按 +20000 规则取 **28080（gRPC）/ 28081（remoting）**，先登记本表与 env.md 再起（E12）。

## 4. 端口规划（核心规则：宿主机端口 = 官方默认端口 + 20000）

- **规则**：全部中间件宿主机端口 = 官方默认端口 + 20000。涉及的全部默认端口均 < 20000，+20000 后落在 22379~38083 区间——好记好查、与宿主机遗留服务（全在默认端口段）天然错开，也避开 Windows 动态端口段（默认 49152 起）；
- **双登记**：下表即登记总表；compose 内每个服务的 ports 行上方必须有注释（例：`# TDengine REST：宿主 26041 → 容器 6041，Basic 认证`），并同步 `micro-deploy/env.md` 登记表；
- **冲突处理**：落地前 `netstat -ano` 核对 22379~38083 号段；若被占，该端口 +1 顺延，**必须回写本文档表、compose 注释、env.md 三处**；
- **例外已有一处**：Gotenberg 与 Grafana 容器默认端口同为 3000，按规则撞车 → Gotenberg 顺延为 **23001**（表与注释中标注例外原因）；
- 业务服务端口（RPC 8081~8095 / BFF 8889~8890 / metrics 91xx / OCPP 8182）**不变**，与中间件新号段互不侵占；
- dev 各端口一律绑定 `127.0.0.1`（如 `127.0.0.1:23306:3306`），仅本机可访问；局域网联调时再显式放开并在 env.md 备注。

| profile | 服务 | 镜像（tag 落地时锁定具体小版本） | 容器端口 | 宿主机端口 | 备注 |
|---|---|---|---|---|---|
| core | MySQL | mysql:8.0 | 3306 | **23306** | 新拉 8.x 镜像；root + 应用账号双账号（§6） |
| core | Redis | redis:7.x | 6379 | **26379** | requirepass；DB0/1/3/4 划分沿用 v2 |
| core | etcd | 官方 etcd 3.7 镜像 | 2379 / 2380 | **22379 / 22380** | 服务发现 + worker_id + APISIX 配置存储 |
| core | TDengine | tdengine/tdengine:3.x | 6041 / 6030 | **26041 / 26030** | REST 必须 Basic 认证（E7）；6030 native 备用 |
| core | RocketMQ NameServer | apache/rocketmq:5.x | 9876 | **29876** | |
| core | RocketMQ broker | apache/rocketmq:5.x | 10911 / 10909 / 10912 | **20911 / 20909 / 20912** | `listenPort=20911` 写进 broker.conf 自洽（E16，§7） |
| edge | EMQX | emqx/emqx:5.8 | 1883 / 8883 / 18083 | **21883 / 28883 / 38083** | TLS 8883 唯一生产口径不变；WS 8083 dev 不映射（OCPP 的 WebSocket 在 iotingest:8182，与 EMQX 无关） |
| edge | APISIX | apache/apisix:3.11 | 9080 / 9180 | **29080 / 29180** | etcd 走容器网 `http://etcd:2379`；dev 不映射 9443 |
| edge | Nacos | nacos/nacos-server:v3 | 8848 / 9848 / 9849 | **28848 / 29848 / 29849** | 客户端按"主端口+1000"推导 gRPC，+20000 规则天然自洽（§7）；若 v3 镜像控制台为独立端口，按 +20000 规则补登 |
| edge | MinIO | minio/minio（锁日期 tag） | 9000 / 9001 | **29000 / 29001** | API / 控制台；init 容器幂等建双桶 micro-file / micro-contract |
| edge | Gotenberg | gotenberg/gotenberg:8 | 3000 | **23001** | ⚠️ 例外：与 Grafana 同默认 3000，顺延 +1 |
| obs | Prometheus | prom/prometheus（v3 系） | 9090 | **29090** | 抓取目标 `host.docker.internal:91xx`（E17） |
| obs | Grafana | grafana/grafana（11+） | 3000 | **23000** | provisioning 自动装配 |
| obs | Loki | grafana/loki（3 系） | 3100 | **23100** | |
| obs | Promtail | grafana/promtail（3 系） | — | 不映射 | 只出站推送 Loki，无需入站端口 |
| obs | Jaeger | jaegertracing/all-in-one:1.57 | 16686 / 4317 / 4318 | **36686 / 24317 / 24318** | UI / OTLP gRPC / OTLP HTTP |
| obs | Alertmanager | prom/alertmanager | 9093 | **29093** | webhook → notification |

## 5. 卷挂载清单（该挂的全挂）

**数据卷**（named volume，`micro-dev_` 前缀；删除容器不丢数据，重置需显式 `compose down -v`）：

| 卷 | 容器挂载点 | 内容 |
|---|---|---|
| micro-dev_mysql-data | /var/lib/mysql | 14 个业务库 + 迁移数据 |
| micro-dev_redis-data | /data | appendonly 持久化 |
| micro-dev_etcd-data | etcd 数据目录 | 服务发现/租约 + apisix prefix |
| micro-dev_tdengine-data / -log | /var/lib/taos、/var/log/taos | 遥测（原始 3 个月 + 降采样 3 年） |
| micro-dev_rocketmq-store | /home/rocketmq/store | 消息存储（含延迟消息/outbox 重试） |
| micro-dev_nacos-data | /home/nacos/data | derby 内嵌配置存储（生产换 MySQL = B8） |
| micro-dev_minio-data | /data | 双桶（普通文件 + 合同桶） |
| micro-dev_emqx-data | /opt/emqx/data | 认证器/ACL（仍配合 bootstrap.sh，E6） |
| micro-dev_prom-data / grafana-data / loki-data / jaeger-data | 各自数据目录 | 指标/看板/日志/链路数据 |

**配置绑定**（bind mount，随仓库走）：§2 目录中的 mysql init、broker.conf、bootstrap.sh、apisix config、prometheus.yml + rules、grafana provisioning、loki/promtail 配置。

**Windows 注意**：bind mount 一律写相对路径（自 compose 文件所在目录起算），规避绝对路径空格坑（E9）；大数据卷用 named volume，不用 bind mount（性能与权限）。

## 6. 密码与账号（全部 .env 注入）

- 命名统一 `MICRO_DEV_*` 前缀，与旧环境凭据一眼区分；
- `.env.example` 入库（占位值 + 注释），`.env` 进 .gitignore；`env.md` 同步登记（dev 凭据仅 dev，沿用 v2 S2-01 约定）；
- MySQL **双账号**：root 仅人工运维用；应用账号由 `mysql/init/01-app-user.sql` 首启创建并授权 `micro_%` 库——业务服务 DSN 不用 root；
- TDengine 必改默认 root 密码（默认 taosdata），envcheck 同步新密码；
- 不开认证的组件（RocketMQ/Nacos/APISIX dev）以**端口回环绑定**兜底，生产策略在各自条目备注。

| 组件 | .env 变量 | 说明 |
|---|---|---|
| MySQL | MICRO_DEV_MYSQL_ROOT_PASSWORD / MICRO_DEV_MYSQL_APP_USER / MICRO_DEV_MYSQL_APP_PASSWORD | 双账号 |
| Redis | MICRO_DEV_REDIS_PASSWORD | requirepass |
| TDengine | MICRO_DEV_TDENGINE_ROOT_PASSWORD | 首启 ALTER USER 修改 |
| EMQX | MICRO_DEV_EMQX_DASHBOARD_PASSWORD | 设备接入账号由 bootstrap.sh 幂等创建 |
| MinIO | MICRO_DEV_MINIO_ROOT_USER / _PASSWORD | |
| Grafana | MICRO_DEV_GRAFANA_ADMIN_PASSWORD | |
| RocketMQ / Nacos / APISIX / Loki / Jaeger / Promtail | — | dev 不开认证或无用户体系；127.0.0.1 绑定兜底；生产按 B8（Nacos）等策略升级 |

## 7. 组网与互通要点（坑位预埋）

| 场景 | 要点 |
|---|---|
| 宿主机应用 → 中间件 | 全部 `127.0.0.1:<新端口>`；各服务 etc/*.yaml 的 DSN 与 envcheck 按 §4 表 |
| 容器 → 容器 | compose 服务名 + **容器**端口（如 apisix → `http://etcd:2379`；GOTENBERG_URL=`http://gotenberg:3000`） |
| Prometheus 抓业务服务 | 业务服务跑在宿主机 → 抓取目标写 `host.docker.internal:91xx`。**容器内 127.0.0.1 指容器自己**（新增 E17） |
| Promtail 收日志 | 各服务 `*_run.log` 统一落盘到约定目录（如 micro-server/logs/），bind mount 进 promtail 容器打标采集 |
| RocketMQ broker | `brokerIP1` 与 `listenPort` 必须等于**客户端实际可达地址/宿主机端口**：dev 全本机 → `brokerIP1=127.0.0.1`、`listenPort=20911`（宿主端口写进容器配置，只改映射不自洽 = 客户端拿到注册地址连不上，新增 E16）；未来服务也容器化时改宿主机局域网 IP（恢复 v2 E3 口径） |
| Nacos 客户端 | SDK 按 `主端口+1000` 自动推导 gRPC 端口 → 宿主 28848/29848 与 +20000 规则天然自洽；若手工改端口必须保持 +1000 关系（E16） |
| TDengine | REST 6041 必须 Basic 认证（E7），envcheck 带认证探测 |
| EMQX | 容器重建后认证器可能随卷外配置丢失 → bootstrap.sh 幂等重跑（E6）；挂 data 卷只降低概率，不豁免该步骤 |
